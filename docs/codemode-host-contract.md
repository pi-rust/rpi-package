# Native Code Mode host contract (implementation v1)

Two worktrees implement this contract together; no MCP or extra model invocation.
The [native parity follow-up](codemode-parity-contract.md) specifies the additive
capabilities, opted-in result envelope, host accounting and parent progress now
required by the current extension.

- Host: `D:/Projects/pi-rust-codemode`, branch `feat/native-codemode`, based on origin/main `2047608`.
- Extension: `D:/Projects/rpi-package-codemode`, branch `feat/native-codemode`, based on origin/main `da0a044`.
- Extend existing runtime action channel: `RuntimeActionId::ToolProgram = 30`. Old hosts must explicitly fail; no direct execution fallback.
- Every operation uses the actual host-owned invocation binding (`__rpi.runtimeHandle` + `__rpi.runtimeKey`, transmitted only as runtime call user_data and reserved `__rpiRuntimeKey`). Never expose keys/handles to guest JS or model.
- Operation `list`: args `{op:"list", offset?:0, limit?:32}`. Reply `{protocolVersion:1, capabilities:{resultEnvelope:1,hostAccounting:1,parentProgress:1}, tools:[{name,description,parameters}], nextOffset:number|null}`. Only the effective active invocation tool set, not arbitrary registry entries. Omit the executing program tool and ancestor tool names. Bound pages and full catalog.
- Operation `start`: args `{op:"start",name:string,arguments:object,timeoutMs?:30000}`. Reply `{requestId:string,status:"running"}`. A unique host call ID is generated; caller cannot supply identity. Actual execution goes through argument preparation/schema validation, before/after hooks and host tool execution safety, never a model turn.
- `poll`: `{op:"poll",requestId}` -> `{requestId,status:"running"|"done"|"failed",result?:{content:[text/image blocks],details,terminate,addedToolNames,usage?},isError?:bool,error?:string}`. Done is a finalized tool result (isError may be true); failed means bridge/lifecycle error. Preserve tool result semantics rather than returning only text. Bounded parent-associated lifecycle/count progress uses the existing outer native update callback, not raw partial payloads across this action.
- `cancel` / `dispose`: `{op,requestId}` -> `{requestId,status:"cancelled"|"disposed"}`. Idempotent within authenticated invocation where practical. Cancel never implies rollback. Disposal must not unload DLL code while workers are still active.
- Bound timeoutMs to 1..120000; max 128 starts and 8 active request futures across an invocation tree, 16 retained requests per invocation; per-result/argument JSON <=1 MiB (reject, not silently truncate). Never auto replay or retry. New starts rejected after parent cancellation/completion, plugin invalidation, session close/switch. Cleanup stays available after cancellation while handle valid.
- The executing program tool must be Sequential (or its loop must be Sequential); the extension registers `parameters["x-rpi-execution-mode"] = "sequential"`, understood by the companion native adapter without changing the ABI layout. Independent nested Parallel tools can still run concurrently within a program. Rust tool-execution panics must also cancel and drain descendants before releasing their containing gate. Finalized termination is latched before any fallible reply encoding. Cancellation/disposal reports failure promptly but retains native execution permits/gates until cleanup finishes; noncooperative native code can therefore delay the parent indefinitely rather than permit unsafe overlap.
- Root and child executions retain their *own* effective tools, cwd and approvals. No authority widening; generic extension calls must not fetch root registry when in a narrowed child.
- Internal calls are descendants of the existing assistant->program tool call, NOT fabricated assistant calls. Do not feed ordinary ToolExecutionStart/MessageEnd into SettlingEmitter: its pending assistant identity check rejects them. Give nested calls parent-associated bounded recording, maintain checkpoint-before-side-effect and conservatively prevent automatic replay of an interrupted program. Reuse existing regular execution primitives without changing ordinary model-call behavior.
- Do not overwrite installed binaries, deploy, modify original worktrees, or introduce Web/ACP/MCP changes. Preserve normal tool visibility.

Extension public API: `codemode` tool, `action:"list"|"execute"` (default execute), `code` required for execute; optional `timeoutMs` 1..120000 default 30000. Execute accepts a JavaScript async body with `return`, no TypeScript compiler. Guest globals: `tools.<name>(arguments)` and `tools.call(name,arguments)`, explicit native output selection with `tools.emit(resultOrContentArray)`, `console.log/info/warn/error`, `print`. `tools.list()` can be implemented from the discovered catalog. No direct fs/network/process/require/import. Native RegExp compiler/runtime intrinsics are unavailable, including literal/dynamic/implicit regex creation: the pinned native backtracking VM is not interruptible. Allocation exhaustion is latched outside JS and cannot be caught to resume host effects or report success. Deadlines remain cooperative, not an OS-enforced hard wall clock. Each invocation has fresh JS state; QuickJS runtime memory/stack/interrupt budgets and bounded logs/results/call count. Promise.all must actually start independent host calls before awaiting them; no synchronous-host-call fake concurrency. Each call returns the finalized result object (reserved host-metadata properties filtered recursively) and rejects on isError with useful error text plus the raw filtered `error.result`. Registration opts into `x-rpi-result-envelope:1`; success, termination and ordinary program failure use the versioned Done envelope preserving native content, details and isError together. Infrastructure/negotiation failures can still use ABI Err. Require all three version-1 parity capabilities before guest execution; there is no fallback to a legacy lenient Done parser. The host, not guest-returned fields, rolls up finalized direct-child usage, deduplicated added names and termination after descendant drain; scripts cannot fabricate accounting. Returned native result objects or explicit emissions promote selected text/image blocks only; ordinary nested JSON and intermediate images are not auto-forwarded. In all exit paths cancel/dispose pending host calls. JS cancellation must escape endless loops/microtasks. ABI poll must remain nonblocking, cancel is signal-only, destroy joins the owner worker.
