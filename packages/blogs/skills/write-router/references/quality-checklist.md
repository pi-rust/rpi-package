# 终稿检查

按题材和任务范围检查，不展示给读者，不以勾选数量验收。具体加工与审稿由 material-to-article、editorial-gate、humanizer 和 empathy-pass 执行。

## 内容与阅读

- 文章确实回答了目标读者的问题，标题兑现阅读收益。
- 核心判断有材料支撑，资料与判断之间的解释已经写进正文。
- 事实、来源观点、推断、示意与亲历分开，版本/环境/统计口径没有混用。
- 没有虚构经历、数据、引语、历史细节或代码行为。
- 每节推进理解，支线服务主线，没有知识目录式拼接和反复总结。
- 源码、架构、机制、评测或排错文章已通过深度闸门：比较对象层级明确；同一个具体动作分别走过两条真实调用路径；入口、核心调用、结果写回、停止/清理和扩展边界可定位；关键不变量写明由谁承担。
- 例子、动作、数据与作者独有观察具体，未被套话磨平。
- 必要术语解释到位，熟悉概念不过度教学；条件、反例与限制放在影响判断的位置。
- 文学/历史的视角、人物、细节和节奏匹配题材，未被强改成教程或论文。
- 有原稿时保住有效论证、事实限定与声音；删改有具体目的。

## 可读与自然

- 语言自然，格式服务阅读，没有宣传腔、模糊权威、机械问句和刻意升华。
- 空泛的“值得注意”等预告没有替代判断；必要的转折和阅读指引可保留，不按词表删除。
- 句子主语和条件清楚，需回读的嵌套句已拆；必要术语在目标读者需要时解释，结论与依据就近。
- 粗体、破折号和引用块有实际信息用途，不靠计数判定合格；列表用于真正并列的事项，连贯论证没有被格式拆散。

## 读者共情

- 开头回应目标读者的具体问题或阅读期待，知识前提与文章深度匹配。
- 主要阻力已在正文得到回应：技术文可定位到术语解释、例子、失败检查或适用边界；文学与历史可定位到人物处境、细节与时代约束。
- 解释顺序符合读者理解所需，而非照搬资料或调试顺序；读后所得明确，不强迫所有题材给操作步骤。
- 没有编造读者经历或用“很多人都……”代替依据；共情不以“我们”的次数或亲切语气证明。

## 资源与呈现

- 外链能找到完整、可复制且可点击的 URL，展示地址与目标一致；代码和图片地址保留正确语法。
- 代码、引用、图表各有信息任务，数据和素材入口可追溯。
- 图片来源、脱敏与图注正确；示意不冒充实测。
- 图表主线、单位、范围、标签与箭头含义清楚，不只靠颜色表达。
- 正文及放大视图中文字、边界和容器裁切已检查；窄屏等未检范围如实说明。
- 图表若是交付重点，正文在相关论述附近提供可见嵌入、图片或明确链接；目标资源在当前构建中可访问，图注写清解释任务与示意/实测边界。仅有静态文件、自动截图或 HTML 生成成功不算可见交付。
- 无图不强制配图，图数、链接数、篇幅不是合格配额。

## 工作结果与交付

- 加工稿记录核心材料、具体解释与成文设计，不只是主题关键词。
- 编辑返修记录实际原句/位置、处理办法与复查结果，不只是“通过”。
- 内容、编辑、机器、渲染和视觉检查各自记录；关键缺口未解决不称终稿完成。
- 复杂技术稿额外记录深度闸门的对象层级、双路径、关键不变量和未解决缺口；没有这些实际记录，不用“结构清晰”代替审稿。
- 声称已实施的修改能在定稿找到替换句；材料加工稿中的关键解释也已写进正文。
- 去 AI 味与共情复核有具体位置和判断依据；需改时记录原句、替换句及复读结果，无需改时记录核验范围与保留理由，不虚构返修。
- 内部工作记录未塞进正文，必要证据、核验入口和参考资料留在文章适当位置。
- 新稿 draft=true，改稿保留原路径与状态，线上发布未擅自执行。
