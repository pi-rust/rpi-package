# 写作路由矩阵

## 任务路由

| 用户目标 | 路由动作 |
|---|---|
| 写一篇文章 | 识别题材后加载一个主模式 |
| 改得更自然、去 AI 味 | 按 `references/humanizer.md` 返修语言与可读性，保留原意和作者声音 |
| 觉得文章读起来费劲 | 用 `references/humanizer.md` 的线索定位超长句、元话语、破折号与粗体 |
| 检查读者能不能读完并愿意照做 | 按 `references/empathy-pass.md` 检查入口、阻力、顺序与出口 |
| 仿照我的风格 | 先读取样文，建立 style profile，再加载题材模式 |
| 做个提纲 | 只输出路由卡、标题方向和骨架 |
| 写开发过程 | `devlog`，有技术细节时加 `technical` |
| 发布文章 | 完成编辑与机器验收，再按项目实际配置和明确授权交接 |
| 用某篇文章评价写作流程 | 以其为校准材料，修改流程和验收，不自动改文章 |
| 只给一句选题 | 收窄读者问题，按 material-to-article 核实资料、形成判断，再设计理解路径 |
| 提供零散资料 | 按问题组织与核对材料，补解释，不按来源各写一段摘要 |

## 意图路由

| 模式 | 典型信号 | 默认辅模式 |
|---|---|---|
| technical | 报错、配置、部署、教程、踩坑、评测 | 仅需要观点与背景时选 longform |
| devlog | 迭代、调试、复盘、协作 | technical |
| longform | 深度、观点、争议、行业观察 | 无默认辅模式；opinionated 仅是风格 |
| source-analysis | 源码、调用链、框架内部 | longform |
| historical | 人物、生平、功过、历史选择 | longform |
| other | 随笔、书评、影评、文案、演讲 | 按读者目的选择 |

## 判定优先级

1. 用户明确指定的文章类型优先。
2. 文章必须完成的任务优先于表面主题。
3. 素材形态用于确认，不单独决定模式。
4. 长度不决定模式。
5. 风格是独立维度，可以跨模式组合。

## 风格画像字段

```text
person: 第一人称 / 第三人称 / 协作视角
rhythm: 短句 / 长句 / 长短交替
register: 口语 / 半正式 / 正式 / 学术
stance: 克制 / 明确 / 尖锐 / 叙事
emotion: 低 / 中 / 高
terminology: 新手 / 混合 / 同行 / 专家
formatting: 小标题、列表、代码、引用、图片
```
