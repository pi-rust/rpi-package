# 博客验收

由 `.rpi/SYSTEM.md` 系统提示词决定进入验收及返工阶段。文章方法见 `skills/write-router/SKILL.md`；本 skill 提供验收方法，不自行编排整篇写作，也不自动发布。

先读取 `skills/write-router/references/editorial-gate.md`、`skills/write-router/references/humanizer.md`、`skills/write-router/references/empathy-pass.md` 和 `skills/write-router/references/quality-checklist.md`，已在本次任务完整读过且未变化的文件无需重复加载。验收包括内容、表达、深度、资源呈现和机器检查；下面的命令只检查机器能验证的部分，不能给整篇文章签发“合格”结论。必须在工作记录中分开写出 `editorial_status`、`machine_status`、`render_status` 和 `visual_status`；任一项未执行只能写 `not-run` 或 `incomplete`，不能用其他项代替。

所有文章先检查 material-to-article 的转化结果：是否回答读者问题、证据支持判断、正文补足解释、每节推进理解；来源摘要拼接和泛化结论不能放行。没有原稿时同样执行，有原稿再增加保留对照。

先查看本篇 work.md：材料加工部分有核心事实及来源、具体解释和限定，编辑返修部分指向正文位置并说明处理结果。缺少这些工作结果时报告具体缺项，由系统提示词返回对应阶段补做，不补写一段形式化“通过”。

逐项查看编辑记录中的原句与定稿替换句，确认修改实际发生且解决问题；确认关键解释落在正文。记录和正文不一致时，返回返修，不能用工作表存在代替内容核查。

源码分析、架构比较、机制解释、评测和排错文章还要执行 `editorial-gate.md` 的“复杂技术稿的深度闸门”：核对比较对象的抽象层，用同一个具体动作追踪两条真实路径，并为取消、顺序、错误、持久化或生命周期等关键不变量标出实际承担者。至少抽查每条路径的入口、核心调用、结果写回和停止/清理位置；只看到模块名、概念表或优缺点总结，不算深度审稿完成。标题若承诺“源码”“调用链”或“从简单到深入”，正文和图表必须兑现这些路径。

对保存后的完整终稿做内容验收，局部任务只读授权文本及必要上下文。分别记录：

- **可读与自然**：复读开头、术语密集处、关键解释和结尾，核对长句、空泛预告、机械对偶、格式强调是否妨碍理解。计数只用于定位，不设“AI 味分数”或标点配额。
- **读者共情**：按目标读者的知识前提，检查入口、主要阻力、解释顺序和阅读所得。用正文位置说明问题怎样被回应；增加“我们”或情绪词不能证明已解决。
- **实际返修**：有问题时核对原句、替换句与段落复读结果；无问题时记录检查范围、具体依据和无需修改的理由，不要求虚构替换句。

事实和结构问题交回相应阶段；语言或共情问题交回阶段六。任何后续修改都要复查受影响内容，必要时重跑机器和呈现检查。上述内容验收未完成时，即使构建成功也不能宣称终稿通过。

1. 对目标文章调用项目 MCP `blog_check`，或 `python scripts/blog_runtime.py check content/blog/文章.md --zola`。新文章加 `--expect-draft`，已有文章保留原 draft 状态。
2. 修复目标文章引入的错误。全站旧问题单独报告，不借验收批量改其他文章。警告逐项判断，不把所有警告机械改写成错误。
3. 外链需要验证时使用 `--external-links --zola`。默认只检查本地内容，不能把未执行外链请求称为链接可访问。403、429、网络失败不直接证明链接永久失效。
4. 使用 `task dev` 预览目标页。通过已配置 Playwright 查看桌面和窄屏；有图片、公式和 Mermaid 时检查成功渲染，并查看正文与放大视图。通过 `image_view` 检查图片，确认中文字、坐标、图注、容器裁切和脱敏效果。
5. 公开图片、图表、架构图和其他文章资源默认应已上传到项目约定的 S3 兼容 `assets` 桶，并由 CDN URL 引用。逐项核对对象路径、Content-Type、源站回源 URL、CDN URL 和访问结果；正文不能引用 RustFS 内网地址或本地临时路径。未上传、未验证或验证失败时，资源验收记录为 `not-run` 或 `incomplete`，不能记为通过。
6. 图表或交互页面不能只生成在项目目录后就算交付：确认正文在相关论述附近有可见的嵌入、图片或明确链接，链接目标在当前构建中可访问，图注说明它回答的问题与“示意/实测”的边界。若交付给用户的是本地预览 URL，必须保持预览服务运行或同时给出可复现启动命令；服务已停止时不得把旧 localhost 地址称为可访问成果。仅有 `static/` 文件存在、HTTP 200、自动截图或 `validate` 通过，都不能替代实际页面中的可见性检查。
7. 有原稿/素材时使用 draft_compare 辅助找出保留项变化，再逐项审读事实限定、数据口径、失败与反例、解释细节、核验入口和图表；风格样稿不提供本篇事实。仅作摘要时按授权范围判断，不能要求全部保留。
8. 按 editorial-gate 以编辑视角复核标题承诺、具体证据、作者声音和理解路径，指出具体问题、在原稿内返修、复查受影响的论断。质量退化或核心事实待核实时不放行；机器检查成功不能覆盖这些问题。代码是否可运行由实际运行及版本证据决定，不执行任意文章代码。

交接简述：检查了哪个文件、机器检查结果、外链检查范围、页面渲染与视觉验收范围、尚未解决的事项。机器通过不代表事实已核验；未使用浏览器不能称视觉验收通过。
