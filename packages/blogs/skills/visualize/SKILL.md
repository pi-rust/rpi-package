# Visualize：博客可视化

本 skill 将 Codex bundled `visualize` 1.0.49 的信息设计、数据表达和可读性原则适配到本仓库。
只使用项目内资源和当前实际可用工具；文章输出不依赖 Codex 对话的专用渲染器、CSS token、组件或宿主 API。

涉及文章创作、改稿或发布前整理时，先经过 [write-router](../write-router/SKILL.md)。
本 skill 处理图解与图表，完成后回到写作路由的终稿检查，不代替正文写作和发布流程。

## 选择能回答读者问题的形式

先写清图要解释的问题、依据的材料，以及正文用它支持哪个判断。仅在可视化能减少理解成本或提供证据时添加，不因文章较长就凑图。

本项目的架构图优先使用 [archify](../archify/SKILL.md)，包括已有架构图的重绘；只有用户指定其他格式，或任务只是少量步骤的正文流程图时，再选择 Mermaid 等工具。正文放静态图，交互版链接并入对应图注说明，不单独堆一段工具入口。

| 读者要理解什么 | 优先形式 |
|---|---|
| 少量数字、结论或映射 | Markdown 表格 |
| 简单职责、条件、数据流和调用关系 | 简洁 Mermaid 图；写入正文前读取 `optional-skills/mermaid/SKILL.md` 并跑校验 |
| 精细架构、流程、时序、数据流、状态关系及交互 HTML；ERD、类图、树、时间线、耗时瀑布 | 读取默认技能 [archify](../archify/SKILL.md) |
| 代码里谁依赖谁、模块/包结构 | 按需读取 `optional-skills/drawio/SKILL.md`，从其导入器得到可编辑 .drawio |
| 需要出版级排版的长图（架构、流程、时间线） | 按需读取 `optional-skills/diagram-design/SKILL.md` |
| 实测数值、时间趋势、分组比较和截图前后对比 | 按需读取 `optional-skills/blog-charts/SKILL.md`，生成 PNG/SVG |
| 重复测量分布、误差范围等专门统计图 | 标准绘图工具；基础 helper 不支持时按数据口径另写脚本 |
| 参数改变如何影响结果、步骤推进或状态切换 | 项目内 HTML/JavaScript 交互解释 |
| 封面、视觉隐喻、宣传插画 | 按需读取 [image](../image/SKILL.md)，与实测图表区分 |

命名数值比较优先用直接标值的条形图；时间或有序变量用曲线；重复测量展示散点、范围或分布。
多个指标采用小图并列，各自标单位和坐标尺度；不能把吞吐、毫秒和 MiB 混成一个无量纲“性能分”。

helper 都在项目内。archify 位于默认发现目录 `skills/archify/`，其余图表 helper 在 optional-skills，不加入默认发现。单张图选一个负责它的技能，不同时加载多套正文。Archify 解释结构与交互，mermaid 承担正文内可渲染的源码级流程图，drawio 从源码抽取模块与依赖边，diagram-design 负责排版表现，blog-charts 表达数值，封面与插画仍走 image。源文件、独立依赖与校验方式见 [图表技能说明](../../docs/writing/visual-skills.md)。

## 源码绘制流程图

要把代码结构画成图时，先确定这张图断言的是什么：

- **静态依赖**（模块 A import 了 B）：用 `optional-skills/drawio` 的导入器，或 `python scripts/blog_diagram.py code-graph <目录> --lang rust`。它能给出带文件来源的边，但不证明运行时调用顺序。
- **执行顺序**（读到请求后依次经过谁、在哪分支返回）：按源码阅读结果手写 `flowchart` / `sequenceDiagram`，用 mermaid 技能的 `check.sh` 校验后再进正文。
- **两种都需要**：先由导入器定骨架，再人工补时序与条件边，图注说明哪部分是静态推断、哪部分来自实际跟踪。

源码图必须记录仓库提交或文件范围；改动源码后重跑导入器，而不是凭记忆补一条边。

## 数据与证据

- 从用户提供或已核验的原始数据绘图，保存数据来源和可重跑的生成脚本。没有数据时不编造测量点、提升比例或不确定性。
- 说明样本数、统计方式、单位、配置和时间范围。区分两端中位数之比、配对比值中位数和合并请求百分位数。
- 重复测试保留全部轮次，尽量展示波动。实测最小值/最大值不是置信区间；统计区间需要相应计算依据。
- OOM、错误、超阈值和缺测单独标记。失败运行的吞吐不作为正常性能点，也不把缺测画成零。
- 默认配置、调参对照和不同环境分别统计；比较条件不同的项目要在图注说明。
- 条形长度默认从零起；如其他图使用截断、对数或双轴，明确标示并说明用途。坐标范围包含数据及误差范围。
- 标出重要数值与单位，解释越高还是越低越好；颜色映射在全文保持一致，配合名称、形状或线型。
- 模型、插值、估算与实测分开标注，连线不表示中间点已经实测。示意图不能冒充实验截图或测量证据。

## 静态图表与文章落盘

评测、研究和需要导出分享的图优先用 Matplotlib 等标准工具；简单关系图使用本项目已有的 Mermaid 渲染。
优先输出 SVG 或足够清晰的 PNG，依据文章正常阅读宽度调整布局，保持中文、单位和数值可读。

文章图片通常放在 `static/images/<article-slug>/`，正文通过 `/images/<article-slug>/<filename>` 引用。
生成脚本及小型源数据按用途保存在项目目录中，避免把机器临时路径或全局插件缓存路径写入待发布文章。
修改已有文章时沿用原文件及关联资源，不为每次图表调整复制一篇新文章。

图注说明数据来源、统计口径和图中符号，并在正文解释该图支持什么判断。正文已经讲清的内容不在图中堆成长段落。

## 交互解释

交互只增加对变量、状态或步骤的理解所需的控件。一个解释以一个主图为中心，默认不增加无关指标卡、筛选器和仪表盘。

- 先检查本项目现有模板和渲染能力，使用项目内 HTML/CSS/JavaScript；与文章无关的页面或模板不随图表任务改动。
- 提供可独立使用的样式、初始化和必要的依赖，不假设有对话平台的全局组件、自动 tooltip 或状态 API。
- 数据及演示状态本地处理，模拟结果标明假设；没有真实接口时不声称已连接业务服务。
- 窄屏下堆叠子图或减少次要标签；SVG 根据容器尺寸布局，不能仅缩小大画布使文字无法阅读。
- 提供键盘可用的原生控件、可见标签、触屏可用交互，并尊重减少动画的设置。
- 给文章提供静态图或文字等价说明，关键结论不能只有悬停时才能看到。

## 验收与交接

回算图中关键数字，与正文、表格及原始数据核对；检查图例、单位、缺测、错误标记和各对照条件。
实际查看生成图片，并在文章预览页检查正文大小及放大视图；交互还需检查默认状态、控件变化、窄屏和运行错误。
图中文字不得与边框、曲线、标签重叠，也不能被主题容器裁切。放大功能不能替代正文可读性。

分别记录语法检查、成功渲染和视觉验收；缺少浏览器或渲染工具时说明尚未完成的检查，不把文件存在当成验收通过。
交接时简要说明保存位置、图表解释的结论、数据来源和验证范围，由系统提示词决定后续审校、验收或返工。
